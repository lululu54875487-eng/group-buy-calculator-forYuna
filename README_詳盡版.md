## 用途與適用情境

本工具主要提供以下協助：

- 依團購組合優惠與折扣碼，計算各品項應分攤的價格。
- 處理不參與折數計算的加購品。
- 設定贈品金額，並選擇是否將其平均折入團購品項。
- 核對主購結帳金額與湊團總價是否一致。
- 複製文字認購清單，供團員在箭頭後填上名字。
- 將填好名字的清單整理為各人的品項與小計。
- 依相同品名統計認購筆數，製作到貨清點表。
- 貼上既有清單，快速建立可編輯的品項。

它不是完整的訂單、付款或物流系統。目前沒有帳號登入、付款紀錄、庫存管理、物流追蹤或跨裝置同步功能。

## 開啟方式與環境需求

### 開啟方式

1. 準備團購計算器的 HTML 檔案。
2. 使用支援 JavaScript 的現代瀏覽器開啟。
3. 在頁面直接輸入資料，不需要安裝套件或執行建置。

程式的 HTML、CSS 與 JavaScript 都寫在同一份檔案，沒有引用外部函式庫或遠端樣式。

### 建議環境

- 使用近期版本的 Chrome、Edge、Safari 或 Firefox。
- 開啟 JavaScript。
- 若要使用複製功能，瀏覽器必須允許頁面寫入剪貼簿。
- 可在電腦或手機瀏覽器使用；部分欄位有手機版排版設定，實際呈現仍會受到螢幕寬度影響。

> 計算與文字整理本身不需要連接後端。剪貼簿功能則受瀏覽器、安全來源與權限限制；直接開啟本機檔案時是否可用，需依實際瀏覽器確認。

## 第一次使用：快速上手

建議按照以下順序操作：

1. **輸入團購品項名稱與各筆原價。**
2. **輸入優惠總金額 A 與折扣碼 B。**
3. **視需要新增加購品及贈品。**
4. **先完成贈品「平均折入」設定，再按「💰 團購價計算」。**
5. **檢查主購結帳金額與湊團總價。**
6. **若出現差額，再手動微調團購價，直到顯示 ✅。**
7. **填寫寄送方式與運費說明。**
8. **按「📋 一鍵複製認購清單」，貼到團購社群。**
9. **等團員填完名字後，將完整清單貼入「📑 整理成明細資料」。**
10. **依需求產生個人明細或到貨清點表。**

> **重要順序**：先做自動計算，最後才手動調價。手動調完後不要再按「團購價計算」，否則會覆蓋手動設定。

## 畫面區塊與功能介紹

### 1. 優惠折數計算

| 欄位 | 用途 | 填寫方式 |
|---|---|---|
| 團購品項優惠總金額 A | 參與折數計算的團購組合優惠價，尚未扣除此處填寫的折扣碼 | 手動輸入 |
| 折扣碼金額 B | 本次另行扣除的折價券或購物金 | 手動輸入；沒有時建議填 0 |
| 團購品項原價總金額 C | 所有團購品項原價的加總 | 系統自動計算，不可直接編輯 |

注意：

- A 應對應「團購品項」區的商品；加購品會另外加總，不要重複放入 A。
- 若 A 已經扣過相同折扣，B 就不應再次填入該筆折扣，避免重複扣款。
- C 只加總團購品項，不包含加購品與贈品。
- 修改 A 會強制重算團購價；修改 B 則進行一般計算，已手動鎖定的價格會保留。

### 2. 同名品項快速設定價格

適用於同一商品出現多列，且希望全部設定為相同價格的情境。

操作方式：

1. 在「搜尋品名」輸入完整品名。
2. 在「快速設定價格」輸入金額。
3. 按「套用價格」。
4. 確認提示中的套用筆數。

例如有三列「高腰褲三件組」，輸入相同品名與價格 `185`，三列的團購價都會變成 `185`。

比對規則：

- 只處理「團購品項」，不處理加購品或贈品。
- 品名前後空白會去除後再比對。
- 其餘文字必須完全相同，不是關鍵字搜尋。
- 「高腰褲三件組」與「高腰褲三件組 黑色」不會視為同名。
- 名稱中間的空格、標點、尺寸等差異也可能導致不符合。
- 套用後會視為手動調價，通常呈現黃底。

### 3. 團購品項

每列由左至右包含：

1. 編號。
2. 品項名稱。
3. 原價。
4. 團購價。
5. 上移、下移、複製與刪除按鈕。

| 操作 | 行為 |
|---|---|
| 新增品項 | 在團購品項最後方新增一列 |
| 上移／下移 | 調整該列在團購品項內的順序 |
| 複製品項 | 將品名與原價等資訊建立為新列，放在團購品項最後方，並觸發重算 |
| 刪除品項 | 刪除該列並重新計算 |
| 團購價計算 | 解除所有團購品項的手動鎖定，重新依折數與贈品分攤計算 |

編號會依「團購品項 → 加購品 → 贈品」的順序連續編排。

目前沒有獨立的數量欄位。若同商品要讓三人各認購一份，建議建立三列，而不是在品名寫「×3」期待程式自動乘算。

團購品項中至少有一筆原價大於 0 時，團購價欄位才會解除唯讀限制。

### 4. 加購品

加購品適用於已有獨立加購價、不需要分攤團購折數的商品。

- 輸入品名與實際加購價。
- 不加入 C，也不乘上團購折數。
- 加購價直接加入主購結帳金額及湊團總價。
- 複製認購清單時會在品名前加上「【加購】」。

例如加購價為 50 元，即直接以 50 元計入，不會再乘折數。

### 5. 贈品

每筆贈品可設定：

- 贈品名稱。
- 主購自行設定的金額。
- 是否勾選「平均折入」。

勾選「平均折入」時：

- 贈品設定金額會平均扣到每列團購品項的自動價格。
- 是依團購品項的「列數」平均，不依原價比例分攤。
- 在湊團總價中，勾選贈品的金額會再加回。
- 加購品不參與這項分攤。

未勾選時：

- 不降低團購品項價格。
- 該贈品金額不加入頁面顯示的湊團總價。
- 但該筆贈品仍會帶著設定金額出現在複製的清單中。

> **請特別注意**：未平均折入的贈品如果設定非零金額，之後整理個人明細時仍會按清單上的金額計入，因此個人明細總額可能與頁面的湊團總價不同。

修改贈品金額時，程式會取消該筆「平均折入」勾選。若仍要分攤，請重新勾選，並重新核對各筆團購價。

### 6. 寄送資訊

可填寫：

- 寄送方式：例如賣貨便、iopen mall 或面交。
- 運費：免運時填 `0`。

這些資訊用於認購清單的文字說明。

**目前運費不會自動加入主購結帳金額、湊團總價或每人小計，也不會自動按人數分攤。**

若有填寄送方式但運費空白，清單仍會將空白運費當作 0，顯示免運。若實際需收運費，請務必輸入並另外核算。

### 7. 總計與核對標記

頁面底部顯示：

- 折數。
- 主購實際結帳金額。
- 湊團總價。
- ✅ 或 ❌。

標記意義：

- ✅：頁面的主購結帳金額與湊團總價完全相同。
- ❌：兩個金額不相同，需要檢查輸入、手動價格或四捨五入差額。

✅ 只代表這兩個數字相等，不代表認購者已填齊、商品數量正確、運費已收，或付款已完成。

## 計算規則與金額範例

### 基本折數

```text
C = 團購品項各列原價加總
折數 r = (A - B) / C
```

若 C 不大於 0，程式會將折數設為 0。

畫面會顯示四位小數，例如 `0.8000`，可理解為八折；實際品項計算使用的是未截成四位小數的原始比例。

### 各品項自動價格

設：

- n：團購品項列數。
- G：所有勾選「平均折入」的贈品設定金額合計，以下以正常非負金額說明。
- P：所有加購品價格合計。

程式計算方式：

```text
每列贈品調整額 = Math.round(-G / n)
各列自動團購價 = Math.round(該列原價 × r) + 每列贈品調整額

主購實際結帳金額 = A - B + P
湊團總價 = 各列目前團購價加總 + G + P
```

沒有團購品項時，每列贈品調整額為 0。

`Math.round()` 為 JavaScript 的整數四捨五入方式。正數的小數為 `.5` 時向上取整；負數恰好在 `.5` 時則朝正無限方向取整，例如 `Math.round(-2.5) = -2`，因此分攤後仍可能有差額。

### 範例一：一般折數

| 品項 | 原價 | 八折後團購價 |
|---|---:|---:|
| 商品 A | 300 | 240 |
| 商品 B | 200 | 160 |

```text
A = 450
B = 50
C = 500
r = (450 - 50) / 500 = 0.8

主購結帳金額 = 400
湊團總價 = 240 + 160 = 400 ✅
```

### 範例二：加購品

延續上一例，加購品價格為 50 元：

```text
主購結帳金額 = 450 - 50 + 50 = 450
湊團總價 = 240 + 160 + 50 = 450 ✅
```

### 範例三：贈品平均折入

同樣兩筆團購品項，新增一筆 20 元贈品並勾選平均折入：

```text
每列贈品調整額 = Math.round(-20 / 2) = -10

商品 A 團購價 = 240 - 10 = 230
商品 B 團購價 = 160 - 10 = 150
加購品 = 50
平均折入的贈品 = 20

主購結帳金額 = 450
湊團總價 = 230 + 150 + 50 + 20 = 450 ✅
```

### 範例四：四捨五入差額

三筆商品原價各為 100 元，A 為 100 元，B 為 0：

```text
C = 300
r = 100 / 300
每筆自動團購價 = Math.round(100 × r) = 33

主購結帳金額 = 100
湊團總價 = 33 + 33 + 33 = 99 ❌
```

可手動將其中一筆改為 34 元：

```text
湊團總價 = 34 + 33 + 33 = 100 ✅
```

手動調整完成後，直接複製清單即可，不要再按強制重算。

## 手動調價與重新計算

### 手動價格鎖定

直接輸入團購價，或使用「同名品項快速設定價格」，會將該列設定為手動鎖定。

一般計算會保留鎖定價格，而不是自動覆蓋。

### 哪些操作會影響手動價格？

| 操作 | 對手動價格的影響 |
|---|---|
| 修改折扣碼 B | 保留鎖定價；未鎖定的列重新計算 |
| 修改某筆原價 | 保留鎖定價；未鎖定的列依新折數計算 |
| 按「一鍵複製認購清單」 | 做一般計算，保留鎖定價 |
| 按「團購價計算」 | 清除全部手動鎖定與黃底，重新計算 |
| 修改優惠總金額 A | 同上，強制重算 |
| 複製團購品項 | 會觸發強制重算，可能覆蓋既有手動價 |
| 勾選／取消贈品平均折入 | 強制重算價格，但不一定同步清除既有鎖定資料與黃底 |
| 刪除贈品 | 同上，強制重算價格 |

黃底是提示，不適合作為唯一的價格狀態判斷；完成贈品設定後先按一次「團購價計算」，最後再做手動微調，最容易核對。

## 複製認購清單

### 操作方式

1. 確認所有品項與金額。
2. 建議將總計調整為 ✅。
3. 按「📋 一鍵複製認購清單」。
4. 貼到社群或其他文字編輯器。
5. 請團員在各列箭頭後方填寫名字。

### 清單範例

以下延續「贈品平均折入」範例：

```text
📦 湊團認購清單

寄送方式📦 賣貨便
運費💰 免運 🚚

優惠組合金額💰450
折扣碼💰50
折數：0.8000

1. 商品 A $230 ➡️
2. 商品 B $150 ➡️
3. 【加購】收納袋 $50 ➡️
4.【贈】小禮物 $20 ➡️

主購實際結帳金額💰450
湊團總價💰450✅
⭐️請在箭頭➡️後方打上名字認購
```

### 注意事項

- 清單依團購品項、加購品、贈品的順序輸出。
- 沒有填品名時會顯示「（未填寫）」。
- 頁面沒有直接編輯認購者的獨立欄位，通常是在複製出去的文字中填名字。
- 由匯入帶入的認購者會保存在列資料中，再次複製時可帶出。
- 複製團購品項不會一併複製原列保留的認購者。
- ❌ 不會阻止複製；程式仍可輸出帶有 ❌ 的清單，發布前請自行核對。
- 贈品是否平均折入不會寫進清單，因此單靠清單無法完整還原這個設定。
- 複製成功提示不等同於已確認剪貼簿寫入完成，請實際貼上檢查。

## 匯入認購清單

### 適用情境

把既有認購清單快速還原成頁面上的可編輯品項，減少逐筆輸入。

**它不是完整備份還原功能**：原始原價、分類與贈品分攤設定未必能從文字清單還原。

### 操作步驟

1. 先複製保存目前頁面的重要資料。
2. 按「📥 匯入認購清單」。
3. 貼上完整清單。
4. 按「📥 確認匯入」。
5. 如果頁面已有資料，確認是否要取代。
6. 查看匯入筆數與警告。
7. 逐筆核對名稱、金額、認購者與總額。

匯入會清空原有團購品項、加購品與贈品，再建立新資料；沒有復原按鈕。

### 建議輸入格式

```text
📦 湊團認購清單

寄送方式📦 賣貨便
運費💰 免運 🚚

優惠組合金額💰450
折扣碼💰50
折數：0.8000

1. 商品 A $240 ➡️小美
2. 商品 B $160 ➡️小明

主購實際結帳金額💰400
湊團總價💰400✅
```

品項列基本規則：

```text
編號. 品名 $價格 ➡️認購者
```

- 品項必須在同一行，匯入功能不會自動把換行拆開的品項接回。
- 編號分隔符號可為半形句點 `.`、全形句點 `．` 或頓號 `、`。
- 品名與 `$` 之間要有空白。
- 價格可解析一般整數或小數，但後續明細整理建議統一使用非負整數。
- 箭頭需使用 `➡️` 或 `➡`，不能改成 `→` 或 `->`。
- 認購者可空白。
- 建議保留組合金額、折扣碼、折數與總額，協助推算及核對。

### 匯入後的實際行為

| 資料 | 目前處理方式 |
|---|---|
| 品名、清單價格 | 建立為團購品項，價格設為手動鎖定 |
| 箭頭後的認購者 | 保留於列資料，再次複製時帶出 |
| 【加購】與【贈】 | 保留在品名，不會自動分到加購品或贈品區 |
| 原價 | 依總額、折數與各筆價格比例推算，不是原始原價還原 |
| 寄送方式、運費 | 嘗試讀取；缺少時清空對應欄位 |
| 原清單編號 | 用於檢查中間是否缺號；頁面會重新連續編號 |

若清單同時含有主購結帳金額與折扣碼：

```text
匯入後的 A = 清單主購結帳金額 + 清單折扣碼
```

若沒有主購結帳金額，才改用清單的優惠組合金額。

因此，清單包含加購品時，匯入後的 A 可能與原 A 不同：原結帳金額已含加購品，但匯入又會把全部品項放進團購品區。

有正折數時，程式會推算原價總額，再依各筆清單價格比例分配到各列；最後一列承接剩餘原價差額。折數缺失或無效時則改以清單價格合計作為推算原價總額的依據。

**不要把匯入後推算出的原價當成商品真正原價，也不要未經核對就按強制重算。**

### 可能出現的警告

- 辨識到的最小編號到最大編號之間有缺號。
- 缺少優惠組合金額或有效折數，無法準確推算原價。
- 清單湊團總價與匯入後合計不相同。

目前不會逐行列出所有未辨識資料；若只有部分列成功解析，其餘列可能被略過。缺號警告也不會完整檢查重複編號、最前端或最後端遺漏，請比對實際筆數。

## 火速整理：每人認購明細

### 功能用途

依認購者彙整品項，列出每個人的商品、小計與固定寄送文字，方便通知認購內容及金額。

### 操作步驟

1. 按「📑 整理成明細資料」。
2. 在上方輸入框貼上已填好認購者的清單。
3. 按「✨ 火速整理🚀」。
4. 在下方唯讀框檢查結果。
5. 按「📋 複製結果」，並實際貼上確認。

**整理功能使用的是上方貼入的文字，不會直接讀取主畫面的品項。**

### 建議格式

每一筆使用：

```text
1. 品名 $價格 ➡️認購者
```

例如：

```text
1. 高腰褲三件組 $185 ➡️小美
2. 襪子 $50 ➡️小美
3. 高腰褲三件組 $185 ➡️小明
```

### 輸出範例

```text
📦 各自認購清單與金額
➡️ @小美
* 高腰褲三件組 $185
* 襪子 $50
💰 小計：235
📦寄送：賣貨便
⸻
➡️ @小明
* 高腰褲三件組 $185
💰 小計：185
📦寄送：賣貨便
⸻
✅ 總金額核對：420
```

### 分組與計價規則

- 依箭頭後方的完整認購者文字分組。
- 同一認購者的多筆商品累積在同一組，小計為這些價格加總。
- 同人重複買相同商品時，明細仍逐筆列出，不會合併為數量。
- 輸出名稱前會加 `@`，並去掉輸入名稱最前方原有的 `@`。
- 但分組使用的是原始名稱，因此「小美」與「@小美」可能分成兩組，儘管輸出看起來相同。
- 名稱前後空白會去除，中間文字或空白不同仍可能分組不同。
- 同一列寫「小美、小明」會被視為一個完整名稱，不會拆成兩人或分攤價格。
- 箭頭後未填認購者的項目不會納入正常的個人認購統計。
- 加購品與贈品在此功能中都以一般文字品項處理，按清單價格加總。

### 格式限制

建議統一遵守：

- 編號使用半形句點 `.`。
- 金額使用半形 `$`，價格使用非負整數。
- 不使用 `$1,000`、`NT$100` 或小數價格等非標準寫法。
- 箭頭使用完整 `➡️`。
- 每列一筆、每筆一位認購者。

「火速整理」與「匯入認購清單」不是同一套解析規則。可成功匯入的格式，不代表一定能成功整理成明細。

程式會嘗試接回某些被拆成多行的品名、價格與認購者，但無法保證所有排版都能還原。原始文字先另存一份最安全，因為執行整理後上方輸入框也會被替換為整理過的文字。

程式另有「編號品名」搭配「一件 $價格 ➡️認購者」的解析分支，但前置換行整理可能影響這種寫法，不建議作為主要輸入格式；每列完整列出品名最可靠。

### 「總金額核對」代表什麼？

它只是把這次成功辨識的認購品項價格加總。

- 不會自動與主畫面的結帳金額比較。
- 不會驗證清單的「湊團總價」文字。
- 不會自動加入運費。
- 即使有品項未被辨識，也可能輸出帶有 ✅ 的總額。

因此，這裡的 ✅ 是固定輸出文字，不等同主畫面真正比較兩個金額後得到的 ✅。

### 寄送文字說明

目前每人小計下方固定輸出：

```text
📦寄送：賣貨便
```

這是文字模板，不會讀取主畫面的寄送方式，也不會建立物流單、運費或寄件紀錄。

### 其他按鈕

| 按鈕 | 功能 |
|---|---|
| 到貨清點表 | 使用上方文字，改輸出依品名統計的數量表 |
| 複製結果 | 複製下方結果；沒有內容時提醒 |
| 清除所有資料 | 清空這個視窗的輸入與輸出，不會清空主畫面商品 |
| 關閉 | 隱藏整理視窗，不會主動清空其中內容 |

## 到貨清點表

### 功能用途

把成功辨識且有認購者的項目，依完整品名加總筆數，供到貨時逐項核對。

### 操作方式

1. 開啟「📑 整理成明細資料」。
2. 貼入已填好認購者的清單。
3. 按「📦 到貨清點表」。
4. 核對下方結果，再複製使用。

不必先按「火速整理」，兩顆按鈕都會解析上方輸入框的清單。

### 輸出範例

使用前面的三筆認購資料，結果為：

```text
📦 到貨清點表

□ 高腰褲三件組：2 件
□ 襪子：1 件

合計：2 種商品，共 3 件
```

### 計數規則與限制

- 每一筆成功辨識的認購項目算 1 件。
- 品名完全相同才合併；價格不同但品名相同，仍會合併計數。
- 「襪子」、「襪子 白色」與「襪子 黑色」算不同品項。
- 「【贈】襪子」與「襪子」也算不同品項。
- 品名寫「襪子 ×3」仍只代表一筆，不會自動算 3 件。
- 「高腰褲三件組」的一列代表一份商品組合，不會自動拆成三件實體褲子。
- 未填認購者、格式不符或解析失敗的項目可能不會計入。
- 不顯示每人的品項、金額或寄送方式。
- 不會讀取倉庫或物流資料，也不會自動記錄清點進度。
- `□` 是複製出來的文字符號，不是可保存勾選狀態的網頁核取方塊。

若要核對「全部預計到貨量」而不只是已認購量，請額外確認尚未認購的品項。

## 完整操作情境

### 情境一：開一團新的團購

1. 建立每份可認購商品，每份一列。
2. 輸入各筆原價，確認 C。
3. 輸入 A、B，避免折扣或加購重複計入。
4. 建立加購品。
5. 建立贈品，完成平均折入設定。
6. 按「團購價計算」。
7. 若有差額，最後手動微調。
8. 確認 ✅，填寫配送說明並複製。
9. 發布清單，請團員保持格式，在箭頭後填名字。

### 情境二：團員填寫完成後整理金額

1. 保存最終原始清單。
2. 貼入明細整理視窗。
3. 按「火速整理」。
4. 檢查是否每位團員都有出現。
5. 檢查加購與贈品金額是否符合收費約定。
6. 將明細總額與應收總額人工比對。
7. 另行處理運費，貼出各人明細。

### 情境三：商品到貨後清點

1. 使用同一份最終認購清單。
2. 按「到貨清點表」。
3. 按品名核對實際商品。
4. 注意組合商品、不同顏色尺寸及未認購商品。
5. 依需要在貼出的文字或紙本上做記號。

### 情境四：接續既有清單

1. 先保存原清單。
2. 使用「匯入認購清單」建立品項。
3. 確認匯入筆數及警告。
4. 注意加購與贈品目前都會放進團購品區。
5. 原價為推算值，請依真實商品資料重新核對。
6. 尚未核對前不要直接強制重算或發布。

若只是想整理每人金額或到貨數量，不必先匯入主畫面，直接貼進明細整理視窗即可。

## 常見問題與排除方式

### 為什麼團購價不能輸入？

請先在團購品項填入至少一筆大於 0 的原價。加購品或贈品有金額並不會解除這個限制。

### 為什麼顯示 ❌？

可能原因包含：

- 每筆自動價格四捨五入後加總有差額。
- 贈品平均分攤後有差額。
- 手動鎖定價格尚未反映最新折扣。
- A、B、原價或加購金額輸入不正確。
- 匯入後的分類或推算原價與原本不同。
- 使用小數金額造成精確比較差異。

請先確認資料，再決定是否強制重算；不要只為消除 ❌ 而調整不合理的數字。

### 為什麼手動改價後又變回去了？

修改 A、按「團購價計算」、複製品項，或某些贈品操作都會觸發強制重算。請完成這些操作後，最後才手動調價。

### 同名價格為什麼沒有套用？

檢查完整品名是否相同、是否帶有不同尺寸或標點，並確認該商品位於團購品項區。

### 為什麼匯入後贈品或加購品沒有在原分類？

目前匯入功能只建立團購品項。標記會保留在名稱，不會自動分類；這是目前行為，不是已完成的優化功能。

### 匯入後原價為什麼不同？

文字清單沒有保存每筆原價，因此程式只能依總額與折數估算，不能完整復原。

### 明細為什麼少了某個人或某件商品？

確認該列：

- 有半形編號句點、`$`、非負整數價格與 `➡️`。
- 箭頭後有填名字。
- 沒有不必要的斷行、特殊金額格式。

程式不會完整列出每筆解析失敗原因，因此請與原清單人工比對。

### 為什麼同一個人分成兩組？

請統一名字寫法，例如不要混用「小美」與「@小美」，或使用不同暱稱。

### 為什麼明細金額與主畫面不同？

主畫面與明細整理使用不同資料及規則：

- 明細只統計成功解析且有認購者的項目。
- 未平均折入的非零贈品仍可能被明細算入。
- 主畫面可能已修改，但貼入的清單仍是舊版本。
- 明細不會主動比對主畫面總額。

### 為什麼寄送方式填面交，明細仍寫賣貨便？

每人的「📦寄送：賣貨便」目前為固定模板，沒有連動主畫面寄送欄位。

### 為什麼複製提示成功卻貼不出來？

目前程式呼叫剪貼簿後直接顯示提示，沒有等待完成或處理寫入失敗。請：

1. 確認瀏覽器剪貼簿權限。
2. 實際貼到文字編輯器檢查。
3. 若複製整理結果失敗，可選取下方結果文字手動複製。
4. 若主要清單複製失敗，可由有權限的管理者確認瀏覽器環境，或使用適當的 HTTPS／本機開發環境。

### 「清除所有資料」會刪掉整個團購嗎？

明細整理視窗的這顆按鈕只清空該視窗上下兩個文字框，不會清掉主畫面的品項。

匯入視窗的「清除」則只清空貼上的匯入文字。

### 關閉頁面後資料會保留嗎？

程式沒有自動儲存功能。不要依賴瀏覽器偶爾恢復的欄位內容；重新整理或關閉前請另存清單。

## 資料保存與隱私

- 程式沒有使用本機儲存、資料庫或後端 API 保存訂單。
- 目前程式沒有將品項或認購者主動上傳到伺服器的程式碼。
- 複製會將資料放入系統剪貼簿；貼到社群後則受該社群平台的資料政策與存取權限影響。
- 清單可能包含名字、暱稱與購買內容，分享前應確認對象與用途。
- 「一鍵複製」不是自動備份，請另存至適當的私人文件。
- 匯出的文字清單沒有每筆原價與贈品平均折入狀態，不能作為完整可還原的資料備份。
- 使用限制浮水印是文字提醒，不是登入驗證或存取控制。

品項資料主要保存在頁面的輸入欄位與列屬性中；`data-locked` 用於手動價鎖定，`data-buyer` 用於保留匯入認購者。

後續若調整清單格式，應同時檢查匯出、匯入、明細整理與到貨清點，避免某一處產出的格式無法被另一處讀取。
